# 7. DATABASE NOTES

1. The database contains five tables.
2. The user_id relationship connects merchant_profiles to users with One-to-One cardinality.
3. The shop_address_id relationship connects merchant_profiles to addresses with Many-to-One cardinality.
4. The approved_by relationship connects merchant_profiles to users with Many-to-One cardinality.
5. The merchant_hours table has a One-to-One relationship with merchant_profiles because merchant_id is its Primary Key.
6. The product_categories table has a One-to-Many relationship with products.
7. The products table has Many-to-One relationships with merchant_profiles and product_categories.
8. The inventory table has a One-to-One relationship with products because product_id is its Primary Key.
9. The day_of_week column accepts values from 0 to 6.
10. The stock_quantity column cannot accept negative values.
11. The reserved_quantity and reorder_level columns currently have default values of 0 and 10, respectively.
12. The cardinality descriptions document the intended relationships. They do not automatically create Foreign Key constraints.
13. PostgreSQL does not support ordinary Foreign Key constraints between separate databases. Direct Foreign Key connections require the referenced tables to be in the same database.
